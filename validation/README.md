# Software validation

Configure the repository's top-level CMake project in a new directory; validation
is now part of that build, not a standalone `cmake -S validation` project.
With Geant4 environment/datasets and ROOT/PyROOT available:

```sh
cmake -S . -B ../../build/cygno-final -DCMAKE_BUILD_TYPE=Release \
  -DCYGNO_BUILD_ANALYSIS=ON -DPython3_EXECUTABLE="$(command -v python3)"
cmake --build ../../build/cygno-final --parallel
ctest --test-dir ../../build/cygno-final --output-on-failure
python3 validation/run_checks.py bi212 ../../build/cygno-final
```

Ensure that the chosen Python actually imports ROOT; CMake can otherwise find an
unrelated Python installation. The tested local interpreter is Homebrew Python
3.14.7. CTest writes logs/results beneath the build directory. Transport and
analysis fixtures use new temporary subdirectories so repeated checks retain
previous results. Geometry diagnostics can be refreshed in their test directory.
The saved historical baseline is separate and is never regenerated by tests.

| Test group | Checks |
|---|---|
| source_and_mass | 90 same-event vertices across nine components, event-zero non-origin, both RNG states, source commands, isotope update, all component mass totals/keys; containment report without resampling |
| source_and_mass_legacy | Same source/RNG/mass checks using the legacy layout |
| layout_profiles | Both profile IDs, ordered module/gas IDs and centers, occupied bounds, vessel/World dimensions; invalid profile rejection |
| layout_geometry | Both actual constructions compared for all 43 local placements/module, historical center fixture, disjoint envelopes, gas/vessel/World containment, source lists; 20-event Po-212 smoke per profile, explicit/default current raw equality, malformed CLI rejection |
| geometry | 75 modules, 150 sensitive cells, 3,227 unique placements, 43 local placements/module, exact layout/copy IDs, materials, disjoint envelopes, vessel/World bounds, nine source lists, inherited overlap report |
| transport | Fixed-seed Po-212 smoke; Bi-211 full, partial, stopped chains; two workers; schema/row validity, gas-cell positions, actual primary and chain summaries; multiple-run ntuple lifecycle |
| analysis | Hand-calculable ROOT fixtures for EOF, event/ionization boundaries, volume ordering, long labels, empty/ignored trees; all normalized plotters retain equal and zero integrals; normalization guards and exact historical table transcription |
| root_geometry | All four actual plot sources compile; 150 ROOT gas centers match Geant4, with original 20 mm fiducial boundaries |

`geometry_snapshot` records materials, solids, placements and source lists.
It accepts an optional profile after the output path. `geometry_audit` accepts
`--layout PROFILE` after the output path (and optional `overlaps` flag).
`python3 validation/run_checks.py layouts /path/to/build` runs the two-profile
validation independently of the rest of CTest.
`geometry_audit` exports TSV with solid signatures and bounds; its optional
`overlaps` argument scans representative internal geometry. `check_geometry.py`
retains the older 25 × 3 migration check, and `--same-layout` compares 5 × 5 × 3
inputs. Do not pass a modern baseline as an old-layout reference without that flag.
`check_hits.py` accepts worker files from **one run**. Events without gas hits need
not appear. `compare_hits.py` compares exact schema and every row without sorting.

## Recovery checkpoints

Before source-order correction, four fresh single-worker runs exactly matched the
saved 05a2b92 output: smoke 7,637; full chain 25,318; partial chain 24,361; stopped
chain 24,395 rows. Branch order/types and all event, particle, position, energy,
volume, nucleus and process values matched. Geometry and placement files were
byte-identical. All six saved schema+row hashes, including the two baseline worker
files, were verified with the previous session's serialization method:
`sha256(json.dumps([schema, rows], separators=(',', ':')).encode())`.
They are content hashes, not byte hashes of ROOT container files.

After source-order correction, the reference single-worker counts on the same
installation are smoke 13,509; full chain 28,319; partial chain 27,180; stopped
chain 27,292. These intentionally differ from historical physics outputs. Tests
check invariants rather than imposing these version-specific counts. MT results
also depend on scheduling; exact matching against the baseline worker split is
not an acceptance condition. Repeated `/random/setSeeds` does not reset the
separate Geant4 solid-surface RNG across runs.

Bi-212 remains an expected `PART122` failure, reported separately by `run_checks.py
bi212`; an unexpected outcome makes that diagnostic fail for investigation.
Passing tests establish software properties, **not scientific model validation**.
See [the recovery report](../docs/REFACTOR_REPORT.md) for artifact locations and
[known issues](../docs/KNOWN_ISSUES.md) for unresolved engineering/physics decisions.
